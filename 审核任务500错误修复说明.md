# 审核任务 500 错误修复说明

## 问题描述

访问审核任务列表时返回 500 错误：
```
column audit_tasks.sampleId does not exist
```

## 问题原因

**数据库列名不匹配**：
- 数据库中的列名使用**蛇形命名**（snake_case）：`sample_id`, `auditor_id`, `submitted_at` 等
- SQLAlchemy 模型中使用**驼峰命名**（camelCase）：`sampleId`, `auditorId`, `submittedAt` 等
- 没有指定列名映射，导致 SQLAlchemy 生成的 SQL 查询使用了错误的列名

## 错误的 SQL 查询

```sql
SELECT audit_tasks.id, audit_tasks."sampleId", audit_tasks.level, ...
FROM audit_tasks
```

数据库中实际的列名是 `sample_id`，而不是 `sampleId`。

## 解决方案

在 SQLAlchemy 模型中为每个驼峰命名的属性指定数据库列名映射。

## 技术说明

### SQLAlchemy 列名映射

SQLAlchemy 的 `Column()` 函数第一个参数可以指定数据库中的实际列名：

```python
# 语法
属性名 = Column('数据库列名', 类型, ...)

# 示例
sampleId = Column('sample_id', String, ...)
```

这样：
- Python 代码中使用 `sampleId`（驼峰命名）
- 数据库中使用 `sample_id`（蛇形命名）
- SQLAlchemy 自动处理映射

### 命名约定

**Python/JavaScript（前端）**：
- 使用驼峰命名（camelCase）
- 示例：`sampleId`, `auditorId`, `submittedAt`

**数据库（PostgreSQL）**：
- 使用蛇形命名（snake_case）
- 示例：`sample_id`, `auditor_id`, `submitted_at`

**SQLAlchemy 模型**：
- 属性名使用驼峰命名（与前端一致）
- 通过 `Column()` 第一个参数映射到数据库列名

## 预防措施

### 1. 使用统一的命名约定

在创建新模型时，始终为驼峰命名的属性指定数据库列名：

```python
class MyModel(Base):
    __tablename__ = 'my_table'
    
    # ✅ 正确：指定列名映射
    myField = Column('my_field', String)
    
    # ❌ 错误：没有指定列名映射
    myField = Column(String)
```

### 2. 使用 Alembic 迁移

使用 Alembic 管理数据库迁移，确保模型定义与数据库结构一致：

```bash
# 生成迁移脚本
alembic revision --autogenerate -m "描述"

# 应用迁移
alembic upgrade head
```
