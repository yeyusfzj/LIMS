### 2. bcrypt 并发问题修复 ✅
**问题**: passlib 的 bcrypt 后端在高并发下初始化失败,导致 "password cannot be longer than 72 bytes" 错误

**尝试方案 1** (失败):
- 预初始化 passlib 的 CryptContext
- 在模块加载时执行一次哈希操作
- **结果**: 无效,因为 passlib 使用延迟初始化

**最终方案** (成功):
- 移除 passlib 依赖
- 直接使用 bcrypt 库进行密码哈希和验证
- 避免了 passlib 的复杂初始化逻辑

**修改文件**: `app/services/auth_service.py`

**代码变更**:
```python
# 之前: 使用 passlib
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 之后: 直接使用 bcrypt
import bcrypt

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return bcrypt.checkpw(
        plain_password.encode('utf-8'),
        hashed_password.encode('utf-8')
    )

def hash_password(password: str) -> str:
    salt = bcrypt.gensalt(rounds=12)
    hashed = bcrypt.hashpw(password.encode('utf-8'), salt)
    return hashed.decode('utf-8')
```

**效果**: 消除了并发初始化错误,登录端点不再返回 500 错误

## 未解决的问题

### 1. 响应时间仍然过长 ❌
**当前状态**: 平均 2.1秒,目标 < 200ms
**差距**: 超出目标 10倍以上

**可能原因**:
1. 中间件链开销过大
   - 日志中间件
   - 限流中间件
   - CORS 中间件
   - 认证中间件
2. 数据库查询未优化
   - 缺少必要的索引
   - N+1 查询问题
   - 未使用查询缓存
3. 缺少 HTTP 连接复用
   - 测试客户端未使用 keep-alive
   - 每次请求都建立新连接
4. 同步阻塞操作
   - 某些操作可能阻塞了事件循环

**建议后续优化**:
- 使用性能分析工具(如 py-spy)定位瓶颈
- 优化中间件链,移除不必要的处理
- 添加查询缓存(Redis)
- 优化数据库查询,添加索引
- 使用连接池和 keep-alive
