## 2. API 端点路径一致性

### 2.1 路径前缀

| 后端 | 前缀 | 说明 |
|------|------|------|
| Node.js | `/api` | 所有 API 端点 |
| FastAPI | `/api/v1` | 所有 API 端点（包含版本号） |

**状态**: ⚠️ 部分一致

**说明**: FastAPI 使用 `/api/v1` 前缀以支持 API 版本管理，这是更好的实践。前端可以通过配置适配两种前缀。

**建议**: 
- 选项 1: 保持 FastAPI 使用 `/api/v1`，前端配置适配
- 选项 2: FastAPI 同时支持 `/api` 和 `/api/v1` 两种前缀

## 12. 发现的不一致问题及修复

### 12.1 响应格式问题

**问题**: FastAPI 响应缺少 `success` 字段

**影响**: 前端无法统一判断请求是否成功

**修复**: 
- 更新 `app/schemas/response.py`
- 添加 `success` 字段到所有成功响应
- 更新所有路由使用新的响应格式

**状态**: ✅ 已修复

### 12.2 分页字段命名问题

**问题**: FastAPI 使用 snake_case (`page_size`, `total_pages`)

**影响**: 与 Node.js 的 camelCase 不一致

**修复**:
- 更新分页响应模型使用 camelCase
- 使用 Pydantic 的 `alias` 功能支持两种命名

**状态**: ✅ 已修复

### 12.3 错误响应结构问题

**问题**: FastAPI 错误响应包含额外字段

**影响**: 与 Node.js 错误响应格式不一致

**修复**:
- 简化错误响应结构
- 只保留 `error` 对象
- 移除 `success` 和 `data` 字段

**状态**: ✅ 已修复
