# 审核API连接修复需求文档

## 介绍

审核功能的前端组件（AuditTaskList.vue 和 AuditTaskDetail.vue）目前使用模拟数据，没有与后端API建立连接。虽然后端已经实现了完整的审核API（auditController.ts 和 auditService.ts），前端HTTP客户端（http.ts）也已配置，但前端审核组件没有使用这些API，导致审核按钮点击后没有实际效果，用户无法完成真正的审核操作。

## Bug分析

### 当前行为（缺陷）

1.1 当用户在审核任务列表页面加载数据时，系统使用硬编码的模拟数据，不调用 GET /api/audits API

1.2 当用户点击"查看详情"按钮时，系统显示模拟的任务详情，不调用 GET /api/audits/:id API

1.3 当用户在审核详情页面点击"通过审核"按钮时，系统仅显示成功消息，不调用 POST /api/audits/:id/review API

1.4 当用户在审核详情页面点击"退回"或"要求补充"按钮时，系统仅显示成功消息，不调用 POST /api/audits/:id/review API

1.5 当用户在审核列表页面点击"快速通过"按钮时，系统仅显示成功消息，不调用 POST /api/audits/:id/review API

1.6 当用户刷新页面时，系统显示的仍是相同的模拟数据，之前的"审核操作"全部丢失

### 预期行为（正确）

2.1 当用户在审核任务列表页面加载数据时，系统应调用 GET /api/audits 获取真实的审核任务列表

2.2 当用户点击"查看详情"按钮时，系统应调用 GET /api/audits/:id 获取真实的审核任务详情

2.3 当用户在审核详情页面点击"通过审核"按钮时，系统应调用 POST /api/audits/:id/review 提交审核决策并更新状态

2.4 当用户在审核详情页面点击"退回"或"要求补充"按钮时，系统应调用 POST /api/audits/:id/review 提交相应的审核决策

2.5 当用户在审核列表页面点击"快速通过"按钮时，系统应调用 POST /api/audits/:id/review 提交通过决策

2.6 当用户刷新页面时，系统应从后端获取最新的审核状态，显示真实的审核进度

### 不变行为（回归预防）

3.1 当后端API正常响应时，系统应继续正确显示审核任务的基本信息（任务ID、样品名称、审核级别、状态等）

3.2 当用户具有审核权限时，系统应继续正确显示审核操作按钮和表单界面

3.3 当审核任务状态为"已通过"或"已退回"时，系统应继续正确禁用审核操作按钮

3.4 当网络连接正常时，系统应继续保持现有的页面布局、样式和用户交互体验

3.5 当API调用失败时，系统应继续正确显示错误提示信息
