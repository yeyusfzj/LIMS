# Bug修复需求文档

## 简介

审核任务列表和详情页面中样品信息显示不完整的问题。当用户查看审核任务时，只能看到基本的任务信息（任务ID、审核级别、状态）和样品的最基本信息（样品编号），但缺少关键的样品详细信息（样品名称、客户名称、样品类型、采样日期、检测项目、检测方法等），导致审核人员无法充分了解样品背景就进行审核决策。此外，数据库种子数据中缺少审核任务的示例数据，影响测试和演示。

## Bug分析

### 当前行为（缺陷）

1.1 当后端API查询审核任务列表时，系统只返回样品的4个基本字段（barcode、sampleNumber、sampleName、clientName），缺少样品类型、采样日期、检测项目、检测方法等关键信息

1.2 当后端API查询审核任务详情时，系统只返回样品的4个基本字段（barcode、sampleNumber、sampleName、clientName），缺少样品的完整详细信息

1.3 当执行数据库种子脚本时，系统不创建任何审核任务示例数据，导致测试环境中审核任务列表为空或只有一个编号

1.4 当前端显示审核任务列表时，由于后端未返回样品类型、客户名称等信息，前端无法展示这些关键字段

1.5 当前端显示审核任务详情时，由于后端未返回采样信息、检测项目、检测方法、检测结果等信息，审核人员无法全面了解样品情况

### 预期行为（正确）

2.1 当后端API查询审核任务列表时，系统应返回样品的完整基本信息，包括：样品编号、样品名称、客户名称、样品类型、采样日期、样品状态

2.2 当后端API查询审核任务详情时，系统应返回样品的完整详细信息，包括：基本信息（样品编号、样品名称、条形码）、客户信息（客户名称、联系方式）、采样信息（采样日期、采样地点、采样人员）、检测信息（检测项目、检测方法、检测标准）、检测结果（各项指标的检测值）

2.3 当执行数据库种子脚本时，系统应创建至少3个不同状态的审核任务示例数据（待审核、审核中、已完成），每个审核任务应关联完整的样品信息

2.4 当前端显示审核任务列表时，系统应正确展示样品的基本信息字段，包括样品编号、样品名称、客户名称、样品类型，使审核人员能够快速识别样品

2.5 当前端显示审核任务详情时，系统应正确展示样品的完整详细信息，包括采样信息、检测项目、检测方法、检测结果等，使审核人员能够做出充分知情的审核决策

### 不变行为（回归预防）

3.1 当后端API查询不包含样品信息的审核任务时，系统应继续正常返回审核任务的基本信息（任务ID、审核级别、状态、审核人员、提交时间等）

3.2 当后端API处理审核决策（通过、拒绝、退回）时，系统应继续正常执行审核流程逻辑，不受样品信息查询增强的影响

3.3 当前端显示审核任务的审核操作按钮和表单时，系统应继续保持现有的交互逻辑和验证规则

3.4 当数据库种子脚本创建用户、角色、权限、工作流模板、检测方法等其他数据时，系统应继续正常创建这些数据，不受审核任务示例数据添加的影响

3.5 当审核任务关联的样品数据不完整或缺失某些可选字段时，系统应继续正常显示已有的字段，对缺失字段显示默认值或空值，不应导致错误或崩溃
