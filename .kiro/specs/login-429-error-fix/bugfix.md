# 登录429错误修复需求文档

## 介绍

用户在登录页面遇到429 Too Many Requests错误，表示登录请求被限流中间件拦截。这个问题影响了用户的正常登录体验，特别是在开发和测试环境中，用户可能需要频繁登录进行功能验证。

错误堆栈显示：
```
Error: 请求失败(429)
at HttpClient.handleError (http://localhost:5173/src/services/http.ts:128:29)
at AuthService.login (http://localhost:5173/src/services/auth.ts:7:22)
at handleLogin (http://localhost:5173/src/views/Login.vue:54:24)
```

## Bug分析

### 当前行为（缺陷）

1.1 当用户在5分钟内尝试登录超过20次时，系统返回429状态码并显示"请求失败(429)"错误

1.2 当遇到429错误时，前端只显示通用错误消息，没有提供明确的等待时间或重试指导

1.3 当触发限流后，用户无法获得剩余等待时间的信息，导致用户体验差

### 期望行为（正确）

2.1 当用户在5分钟内尝试登录超过20次时，系统应该返回429状态码并提供友好的错误消息，包含剩余等待时间

2.2 当遇到429错误时，前端应该显示具体的限流提示，告知用户需要等待的时间，并提供自动重试选项

2.3 当触发限流后，系统应该在响应头中包含重试时间信息（Retry-After），前端可以据此显示倒计时

### 不变行为（回归预防）

3.1 当用户正常登录（未触发限流）时，系统应该继续正常处理登录请求并返回认证令牌

3.2 当用户登录失败（用户名密码错误）时，系统应该继续返回401错误而不是429错误

3.3 当其他API接口调用时，限流机制应该继续正常工作，不受登录限流修复的影响
