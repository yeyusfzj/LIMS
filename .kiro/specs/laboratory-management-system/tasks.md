# 实施计划：审核管理主体调整（样品 → 实验任务）

## 概述

本实施计划聚焦于将审核管理的主体从"样品"调整为"实验任务"。这是一个小范围的修改，预计在一天内（6-8小时）完成所有修改。

### 核心变更

- **数据模型**：审核任务（AuditTask）的关联从 `sampleId` 改为 `taskId`
- **后端 API**：审核相关接口的参数和逻辑调整
- **前端界面**：审核界面显示任务信息而非样品信息

### 影响范围

- 数据库表结构（1个表）
- 后端服务和控制器（2-3个文件）
- 前端组件（3-5个文件）
- 测试文件（2-3个文件）

## 风险和应对

### 风险 1：数据迁移失败
- **应对**：提前备份数据库，准备回滚脚本
- **预防**：在测试环境充分测试迁移脚本

### 风险 2：关联数据丢失
- **应对**：验证数据完整性，确保所有关联正确
- **预防**：编写数据验证脚本，迁移后自动检查

### 风险 3：前后端接口不匹配
- **应对**：使用 TypeScript 类型检查，及时发现问题
- **预防**：前后端同步更新，保持接口一致

### 风险 4：测试覆盖不足
- **应对**：补充测试用例，覆盖关键场景
- **预防**：制定测试清单，逐项验证
